Problem and opportunity

Security teams can see thousands of exposures but can't tell which few actually lead to their critical assets, and AI agents are now adding a fast-growing class of exposures that their tools don't model at all.

  • Prioritization is broken. 97% of security teams struggle to know which exposures are actually exploitable, 42% of analyst time goes to risks that turn out not to matter, and 84% of SOC teams were hit through risks they already knew about (Filigran survey, vendor-run).
  • AI agents are a new, unmanaged attack surface. 38% of 560 scanned MCP servers had no authentication, 30 MCP vulnerabilities were filed in 60 days, and only 21% of executives have full visibility into what their agents can access (DEV roundup).
  • Analysts agree it's the priority. Two of Gartner's six top cybersecurity trends for 2026 are oversight of AI agents and adapting identity management to them (Gartner).

Why now: agent adoption is moving from pilots to production, while dedicated MCP security startups have raised only about $40M (Software Strategies). Exposure tools that already sit in the budget have no agent-aware prioritization yet, which leaves room for a layer that adds it.

MVP scope

The MVP runs two agents on one fictional company: a discovery agent that finds its AI agents and MCP servers and checks how risky they are, and an analyst agent that turns everything into a top-10 list of attack paths, tickets and a board brief. It uses only free data sources.

In the MVPWhat it doesStatus
InputsScanner findings, an asset inventory with crown-jewel tags, and identities, as JSON files. The AI agent and MCP inventory is not hand-written: the discovery agent builds it.Built
Discovery agentFinds AI agents, MCP servers and RAG pipelines (vector databases and the knowledge bases agents retrieve from) from three sources: MCP config files on laptops and servers (Claude, Cursor, VS Code), read-only probes of MCP and vector database endpoints on an approved scope list, and exported cloud AI inventories (AWS Bedrock agents and knowledge bases, Azure AI Foundry, Azure AI Search). It flags missing authentication, high-risk tools (shell, payments, external email), vulnerable MCP packages such as mcp-remote and MCP Inspector, tool descriptions with hidden instructions, vector stores open without login, knowledge bases fed from untrusted sources, and retrieval that ignores document permissions. SOAR integration

Every output is machine-readable, so security automation can act on it without a person in the loop.

InterfaceWhat it doesStatus
JSON outputscan --format json writes the inventory, findings and ranked paths as JSON with a published, versioned JSON SchemaBuilt
REST APIStart a scan, list ranked paths, get a path's evidence and ticket. An OpenAPI spec is generated automaticallyNext
WebhookPushes each new or worsened critical path to a SOAR endpoint as JSON, signed so the receiver can verify itNext
Example playbookOne working playbook (Cortex XSOAR generic webhook or a Microsoft Sentinel Logic App) that opens a case per critical path and assigns the ticket ownerNext
Integration guideField-by-field schema reference, example payloads and setup steps for the playbook, in the repo docsNext

Not in the MVP: live vulnerability scanning, live cloud API discovery (the MVP reads exported inventories), probing anything outside the approved scope list, calling MCP tools (discovery only lists them), live connectors to scanners and CTEM tools, multiple clients (tenants), user accounts, and automatic fixes.

Core user stories

  1. As an AI platform owner, I want the discovery agent to find every AI agent, MCP server and RAG knowledge base in use, including ones nobody registered, so shadow AI shows up in the inventory. Built
  2. As an AI platform owner, I want each discovered MCP server checked for missing login, high-risk tools and known-vulnerable packages, so I can fix them before an attacker finds them. Built
  3. As an AI platform owner, I want every knowledge base mapped to the sources that feed it and the agents that read it, so a poisoned document or an open vector store shows up as an attack path. Built
  4. As a head of exposure management, I want the 10 attack paths that reach crown-jewel assets, ranked, so my team works on what matters first. Built
  5. As a head of exposure management, I want each path's reason in plain words, so I can defend the ranking to engineers and auditors. Built
  6. As a cloud engineer, I want a ready-to-file ticket with the fix and evidence, so I can act without a meeting. Next
  7. As a SOAR engineer at a company or MSSP, I want new critical paths pushed to my SOAR as JSON, so playbooks open cases and route fixes automatically. Next
  8. As a CISO, I want a one-page brief showing the trend and three asks, so I can take it straight to the board. Next

What the build shows so far

The demo runs on Halden Logistics, a fictional 4,500-person freight company with real CVEs and planted problems. The numbers below come from the published scan result, which the test suite regenerates and compares on every run.

  • The exposure index is 433.4 of 600 with AI discovery, against 245.7 on scanner, CMDB and posture data alone.
  • 7 of the top 10 attack paths run through AI components. 4 of them are invisible without discovery, and 3 more score far lower without it.
  • Discovery finds 19 AI components, 8 of them in no inventory, and raises 25 risk flags, 7 of them critical.
  • 5 fixes cut the exposure index by 78.7%. The first is a VPN flaw that ranks only 11th on a list sorted by CVSS, and 2 of the 5 are agent approval settings that no vulnerability scanner reports.
  • 8 of the 10 highest-CVSS findings lead to no crown jewel at all.

Competitive landscape

Exposure platforms are strong at prioritization but treat AI agents as an add-on, while AI agent security startups find agents but don't rank them against the rest of the attack surface. The gap is joining the two, and the closest player doing so today is Wiz, but only for cloud.

Positioning, packaging and pricing

Position it as the prioritization layer that makes existing exposure tools agent-aware, sell it through MSSPs, and price it per protected asset with agents counted as assets.

Positioning statement. For CISOs at enterprises rolling out AI agents, who can't tell which of thousands of exposures reach their crown jewels, this product is an intelligence-led prioritization layer. It discovers the AI agents and MCP servers in use, ranks attack paths across infrastructure, identities and those agents, then turns them into tickets and a board brief. Unlike exposure platforms that bolt on AI modules, or agent security tools in a separate console, it puts agent risk in the same ranked list, on top of the tools you already own.

Three messages

  • Fix the 10 paths that reach your crown jewels, not 10,000 findings.
  • Find the AI agents, MCP servers and RAG knowledge bases you didn't know you had, and see their risk in the same list as everything else.
  • From raw findings to a board-ready brief in minutes.
